## The previous contents were removed, not lost

The numbers that used to be in this file — 1,428,991 requests, 3,966 req/s, an 88.52% success
rate, a 2,302 ms p95 — were produced by a benchmark that created a URL and immediately resolved
it: a 1:1 write/read ratio against a guaranteed cache hit. They measured a workload no shortener
has, and they are not comparable to anything the current suites produce.

[`BASELINE.md`](BASELINE.md) explains what changed and what a number from this file does and
does not mean.

## What a row will contain

| Column | Meaning |
| :-- | :-- |
| Redirect p95 | Cache-path latency, reported separately |
| Create p95 | Postgres-write latency, reported separately |
| Cache hit | Measured from the `X-Cache` response header |
| Redirect errors | Anything that was not a 301/302 |
| 503s shed | Requests the database bulkhead rejected rather than queued |

And, above the table, the hardware — because a GitHub Actions runner hosting KinD, Postgres,
Valkey, every backend pod *and* k6 is measuring itself at least as much as the application.
